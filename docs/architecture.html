Who decides what

Plain code, every time

  • Distance from the own site (haversine) and the radius cut.
  • Eligibility: new launch or under construction only, possession after today, at least one BHK in common.
  • Merging by RERA number, normalised name, or two pins under 150 m apart.
  • The 6/6 count and the COMPARABLE / PARTIAL / THIN label.
  • Conflicts: rate spread over 15%, mixed basis, possession dates more than 3 months apart.
  • Match score weights: configuration 25, carpet 20, rate 20, possession 15, distance 10, structure 10.
  • Which value to display when sources agree: manual → MahaRERA → propOG → builder site → portals → web.

Claude, with a fixed schema

  • Extract. Reads one page, returns the form with nulls for anything not stated. Told to keep carpet separate from built-up and to record the rate's basis.
  • Same building? Only for pairs the rules could not settle, such as one shared distinctive word and no pins.
  • Narrate. Receives the computed numbers, returns one sentence per card and per comparison section. Falls back to a template sentence if the call fails or no key is set.

Model claude-opus-5 through langchain-anthropic with JSON-schema structured output, so every answer is a validated Pydantic object.
